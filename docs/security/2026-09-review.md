# Demo-readiness review, 2026-09-30

> **Status: all findings below resolved** unless marked otherwise. This is a follow-up to the [2026-06 audit](2026-06-audit.md). It covers the code after the audit fixes, with the same threat model ([`SECURITY.md`](../../SECURITY.md)).

## Method

Five reviewers each owned one area: auth and infrastructure, untrusted input and data flow, backend correctness, the dashboard, and repository presentation. Each finding was reproduced before it was fixed. Probes ran the app in production mode against a throwaway database, a timing harness checked the regexes, and a headless browser took screenshots. The high-severity findings were then independently re-verified. Every bug fix has a regression test that fails without it. The finished branch was re-reviewed by someone who hadn't worked on it.

Fixes are referenced by commit subject. The branch was squash-merged into `master` as `667dc09`, whose message lists every commit subject.

## Fresh-eyes review of the fixes

A reviewer who hadn't written any of the fixes then tried to break them. It ran the README quickstart end to end, compared the old and new parser on 60,000 generated notifications, and reverted each fix one at a time (30 in all) to see whether any test noticed. Nothing it found was Critical or High:

### Known limitations

- **Parser edge cases (RB7).** Two shapes the old parser accepted no longer match: an FX note of more than 40 characters inside the currency parentheses, and a merchant name made only of emoji or punctuation. No real Revolut notification of either shape is known. The bound is what closes the ReDoS.
- **Undo after reclassifying an existing rule.** The rule survives Undo, but it keeps the wallet the classification gave it. Restoring the previous wallet would mean storing it.
- **Migration integrity check.** `foreign_key_check` runs after drizzle has committed the migrations, so a database that already has broken references refuses to boot. That fails safe. Run `PRAGMA foreign_key_check;` on a copy of the production database before deploying.

## Verified sound

These controls were probed and held up:
- **Admin actions.** A normal user gets 403 on every admin action, enforced on the server. The Vue router guard is only cosmetic.
- **Origin and CSRF.** better-auth's Origin check rejects foreign origins. Custom routes are protected by SameSite=Lax cookies, JSON-only validators and CORS preflight.
- **Sign-in.** It is rate-limited to 5 per minute, and there's no account enumeration.
- **Sessions.** Banning or removing a user revokes their sessions immediately.
- **CSP.** Strict: `script-src 'self'`, with `'unsafe-inline'` allowed for styles only.
- **XSS.** No `v-html`. ECharts tooltips HTML-encode names, and the echarts `lines` advisory isn't bundled.
- **Telegram.** The chat-id allowlist runs before every handler, including callback queries, and no message uses `parse_mode`.
- **SQL.** No SQL built from strings.
- **Webhook secret.** Compared in constant time.
- **Logs.** Redacted.
- **Git history.** No secrets in any branch, stash or commit.
